1. Document Purpose

This document defines the design, gameplay systems, presentation, progression, and intended player experience of FiveTen.

FiveTen is an arcade puzzle game built around addition. The player places falling number pieces and creates groups of three adjacent blocks whose values equal the current target.

The game is designed to be immediately understandable while gaining depth through planning, timing, calculation, and mastery.

2. Game Overview

FiveTen is a falling-block puzzle game in which the player combines three adjacent numbers to reach a target.

The initial target is 10. The player must successfully complete the target five times to advance to the next target.

The target increases by 5 each time:

10 → 15 → 20 → 25 → ... → 100

Reaching and completing target 100 results in victory.

The game ends when the board becomes full enough that new pieces can no longer be placed.

The game is primarily an arcade experience. Its mathematical value is secondary to the gameplay.

3. Design Pillars

3.1 Challenge

The player must calculate, plan, react, and manage board space under increasing pressure.

3.2 Flexibility

There should be multiple possible calculations and multiple ways to approach a target. The player should be encouraged to look beyond one familiar formula.

3.3 Reward

Successful decisions should feel meaningful through visual feedback, scoring, combos, special abilities, target progression, sound, and positive reinforcement.

4. Target Audience

FiveTen is intended for anyone capable of basic addition.

The game can also provide incidental educational value by encouraging players to:

  • perform addition repeatedly
  • recognize number combinations
  • calculate faster
  • develop familiarity with number composition
  • make simple calculations more intuitive rather than consciously effortful

The game should not become a conventional mathematics teaching tool. Its identity is primarily an arcade puzzle game.

5. Design Problem

The central design question was:

Can mathematics become the foundation of a real arcade puzzle game?

Addition was selected because it is accessible, common in daily life, and easy to understand.

Other operations were considered less appropriate for the original concept. Multiplication, for example, can make numbers grow rapidly and would push the game toward a different type of puzzle design.

6. Inspirations and Positioning

FiveTen draws inspiration from falling-block puzzle games.

Important inspirations include:

  • Tetris — falling-block structure
  • Puyo Puyo — connected/paired pieces
  • Meteos — falling puzzle-game experimentation
  • Lumines — scanning/clearing rhythm

FiveTen is intended to feel like a celebration of the falling-block puzzle genre while giving it a mathematical identity.

7. Core Gameplay Loop

High-level loop

  1. Receive a falling number piece.
  2. Move and rotate it.
  3. Place it on the board.
  4. Build groups of three numbers.
  5. Match groups whose sum equals the current target.
  6. Wait for the scanner to detect valid groups.
  7. Clear successful groups.
  8. Build combos and charge abilities.
  9. Complete the current target five times.
  10. Increase the target by five.
  11. Continue until target 100 is completed.

Low-level loop

At the moment-to-moment level, the player constantly decides:

  • Which calculation should I build?
  • Should I use this piece now or prepare for a future piece?
  • Should I create one match or multiple matches?
  • Should I protect a potential Stone Combo?
  • Should I wait for the scanner?
  • Should I prepare for the next target?
  • Should I use a charged ability?

8. Core Rules and Objective

A valid standard match consists of:

Three horizontally adjacent blocks whose values add up to the current target.

Example:

5 + 4 + 1 = 10

When the scanner reaches the row containing the valid group, the group is cleared.

The player must complete the target five times before the target increases.

9. Board

The standard board is:

  • 10 columns
  • 17 rows
  • Cell-based placement
  • Falling paired number pieces

The board must remain readable on mobile devices.

Readability is a major design constraint because the numbers are the most important information on screen.

10. Falling Pieces

Pieces consist of two connected number blocks.

The player can:

  • move left
  • move right
  • soft drop
  • hard drop
  • rotate

Number generation is adapted around the current target so that useful calculations remain possible without making the solution completely predictable.

The system also avoids repeatedly producing exactly the same pair.

11. Why Three Blocks?

Three blocks were chosen as the central calculation unit.

Two blocks were considered too easy and would reduce the strategic requirement.

Four blocks were tested and created problems:

  • calculations became more cumbersome
  • the board needed to become larger
  • UI readability suffered
  • smaller mobile screens became inconvenient

Three blocks also benefit from the player's existing familiarity with match-three structures.

12. Target System

The target is the primary objective and the driving force of the game.

The game begins at:

Target 10

The player must achieve five successful target matches.

After five hits:

Target +5

The progression continues until:

Target 100

Target 100 is the victory condition.

13. Why Start at 10?

The starting target was influenced by the name FiveTen and the five-hit structure.

Target 5 was considered too restrictive because it has fewer practical three-number compositions.

Target 10 provides enough combinations to create meaningful decisions while remaining accessible.

14. Why Stop at 100?

The original concept considered going as high as 1000.

The maximum was reduced to 100 because the project needed to remain small and focused.

The intended experience is a compact arcade game that can be completed in a sitting while still providing enough progression and challenge for mastery.

15. Scanner System

The scanner is a central part of FiveTen's identity.

Instead of clearing a valid match immediately, the horizontal scanner moves through the board and detects valid groups when it reaches their row.

This creates:

  • anticipation
  • timing decisions
  • strategic setup
  • combo opportunities
  • a rhythm to gameplay

The scanner also makes combo detection natural without requiring a conventional countdown timer after every match.

16. Scanner Speed and Progression

The horizontal scanner begins at approximately:

0.60 seconds per scan cycle

After each target advancement, its speed is multiplied by:

0.92

The speed has a minimum of approximately:

0.15

This creates increasing pressure as the player progresses.

17. Emergent Scanner Strategy

Playtesting revealed behavior that was not explicitly designed as a separate mechanic.

A player can build a "tower of calculations," wait for the scanner to restart, and then place pieces that create several successful calculations in the same scanning cycle.

This produces a strong feeling of anticipation and payoff.

The important design lesson was:

Small conditions can dramatically change player behavior without requiring an entirely new mechanic.

18. Combo System

Combos are created when multiple valid matches are detected in a sequence.

Combo performance can provide:

  • additional score
  • positive feedback
  • bonus pieces
  • access to special abilities

The scanner provides a natural rhythm for recognizing combo sequences.

19. Reward Feedback

Successful calculations receive intelligence-themed compliments.

Examples include:

  • BRIGHT
  • SHARP
  • CLEVER
  • SMART
  • BRAINY
  • PERCEPTIVE
  • INSIGHTFUL
  • ASTUTE
  • BRILLIANT
  • GENIUS
  • MASTERMIND

The purpose is not simply to announce a score.

The game wants the player to feel:

"I solved that. I am getting smarter/faster at this."

This supports the intended emotional goal of accomplishment.

20. Stone Combo

The Stone Combo occurs when two valid groups of three share exactly one block.

Example concept:

A five-block structure can contain two overlapping valid calculations.

The name comes from the idea of:

hitting two birds with one stone.

The Stone Combo represents:

  • compact calculation
  • efficiency
  • minimal space usage
  • intelligent planning
  • high-level mastery

It was discovered through experimentation rather than being part of the original core specification.

It is one of the game's most important examples of emergent depth.

Stone Combo score:

60 points

21. Vertical Scan

Vertical Scan was added after playtesting.

Players naturally discovered valid vertical arrangements, and the original horizontal-only system made the gameplay feel unnecessarily restrictive.

Vertical Scan allows the system to recognize valid vertical groups.

It also improves gameplay fluidity by expanding the player's possible solutions.

Vertical Scan is charged through combo performance.

Current implementation charges it at approximately:

2+ matches

When activated, the vertical scanner moves through the board and searches columns.

22. Purge Strike

Purge Strike is a recovery and board-management ability.

During playtesting, a problem was observed:

Players naturally tend to force familiar calculations.

For example, when the target is 10, a player may repeatedly try:

5 + 4 + 1 = 10

If the required values do not appear, the player can accumulate similar numbers and gradually fill the board.

Purge Strike provides a controlled escape from this situation.

It identifies the most frequent number on the board and removes its occurrences.

The ability therefore:

  • clears problematic board states
  • provides recovery
  • encourages the player to consider other calculations
  • prevents one bad strategy from becoming immediately fatal

Purge Strike is charged at approximately:

3+ combo

23. Ability Philosophy

The special abilities are not disconnected secondary mechanics.

They are rewards produced by the core gameplay loop.

Example:

2x combo → Vertical Scan

3x combo → Purge Strike

This means stronger play produces additional tools that can improve future play.

The system therefore forms a feedback loop:

Good decisions → combos → abilities → more options → better decisions

24. Next Piece Preview

The next piece preview gives the player information about what is coming.

Its purpose is not merely convenience.

It changes the player's decision-making by allowing anticipation.

The design principle is:

Anticipation with knowledge creates better decisions.

The player can therefore prepare calculations instead of reacting entirely to the current piece.

25. Mobile Controls

FiveTen was designed primarily for touch devices.

Horizontal swipe

Move the piece left or right.

Down swipe

Soft drop.

Fast downward flick

Hard drop.

Double tap

Rotate the piece.

Double tap was selected for rotation because accidental rotation would be particularly disruptive during mobile play.

The touch system also uses:

  • swipe thresholds
  • diagonal dead zones
  • delayed auto shift
  • repeated horizontal movement
  • fast-flick detection

26. Keyboard / Controller Controls

Keyboard/controller input supports:

  • Left / Right → movement
  • Down → soft drop
  • Up → hard drop
  • Accept → rotate

The game therefore retains a conventional control model outside touch devices.

27. Scoring

Current scoring implementation:

Action Score
Soft drop +1 per scored step
Hard drop Up to +20 based on distance
Normal match +25
Stone Combo +60
Combo Base +50, increasing by 10% per combo level after the base
Target completion Target × 50
Final time bonus Elapsed seconds × 10

The final time bonus is applied at the end of the run.

28. Leaderboard

The leaderboard transforms score from a private number into a competitive goal.

Displayed information includes:

  • Rank
  • Country
  • Name / ID
  • Score
  • Highest target
  • Time

Country selection is optional.

The leaderboard is powered through PlayFab.

29. Difficulty and Progression

Difficulty is created primarily through:

  • faster scanner speed
  • higher targets
  • increasing cognitive load
  • board management
  • limited space
  • need for faster calculations
  • need to anticipate future pieces

The game should not simply become difficult by restricting the player constantly.

A strong level-design principle discovered during the project is:

Difficulty can come from freedom of sequence. The tighter the sequence, the more difficult the situation becomes.

The player should experience pressure followed by moments of freedom.

30. Visual Direction

The visual style prioritizes:

  • simple presentation
  • clean UI
  • readable numbers
  • readable text
  • strong information hierarchy

Numbers are the most important visual information.

The visual identity combines educational/scientific readability with a strange medical/surgical theme.

31. Hidden Narrative and Medical Metaphor

The entire game secretly represents a defibrillator scenario.

The player is not explicitly told this at the beginning.

The board represents a patient.

The horizontal scanner functions like a medical scanning process.

The Vertical Scan uses a heartbeat/ECG visual language.

Purge Strike represents external defibrillator paddles/electricity.

The player is effectively trying to save the board's life.

The intention is for players to notice clues and form theories without fully understanding the narrative until the end.

32. Victory Narrative

At the end of the game, after the player successfully reaches the final condition, the board thanks the player for saving its life.

The board then flies away to see its family.

The narrative is intentionally light and unexpected.

The reveal gives meaning to the strange medical visual language that appeared throughout the game.

33. Audio Direction

Audio is used to reinforce:

  • menu interactions
  • countdown
  • successful start
  • game over
  • heartbeat/Vertical Scan
  • Purge Strike readiness
  • Purge Strike activation
  • menu atmosphere

The audio system includes dedicated players for important effects so that critical feedback is not accidentally interrupted.

34. Game Flow

Main Menu

  • Endless
  • Leaderboard
  • Options
  • How To Play
  • Credits
  • Quit

Game Start

A short 3-2-1 countdown prepares the player.

Gameplay

The player places pieces, creates calculations, manages the board, builds combos, and progresses through targets.

Game Over

The game freezes and presents:

  • score
  • target
  • time

The final time bonus is applied.

Victory

The final score is calculated and submitted, followed by the hidden narrative ending.

35. Tutorial Philosophy

The tutorial should teach the game through the smallest possible set of rules:

  1. Falling pieces contain numbers.
  2. Build three numbers.
  3. Make them equal the target.
  4. Let the scanner clear them.
  5. Repeat five times.
  6. Continue toward 100.

Advanced systems such as Stone Combo and special abilities can be introduced gradually through play.

36. Educational Value

FiveTen is not intended to replace mathematics education.

Its educational value comes from repeated, meaningful use of arithmetic inside a fun system.

Potential benefits include:

  • faster addition
  • number-combination recognition
  • intuitive number composition
  • attention
  • planning
  • decision-making

The key design rule is that the player should be playing a game first.

37. EdTech Edition Concept

A school-oriented edition can provide additional configuration and customization.

Potential controls include:

  • target configuration
  • spawn speed
  • difficulty
  • private/classroom leaderboards
  • removal of advertisements
  • school-specific presentation

Possible customization can include:

  • selected music
  • school logo
  • school-specific background
  • branded gameplay presentation

The EdTech version should remain based on the same core game rather than becoming a completely separate educational product.

38. Technical Direction

FiveTen was developed in Godot using GDScript.

Major technical areas include:

  • falling-piece logic
  • board/grid management
  • scanner systems
  • touch input
  • UI scaling
  • PlayFab integration
  • leaderboard submission
  • audio management
  • scene transitions
  • countdown system
  • mobile optimization
  • Android export
  • monetization integration

39. Performance Requirements

Because FiveTen targets mobile devices, visual effects must not compromise gameplay performance.

The project intentionally avoids expensive fullscreen effects where possible.

The countdown, scanner effects, heartbeat effects, and other feedback systems were designed with mobile performance in mind.

UI must remain readable across different device sizes.

40. Monetization

The public mobile version supports advertising.

A paid option can remove advertisements.

The monetization layer should not interfere with the core puzzle experience.

41. MVP Scope

The core MVP consists of:

  • falling number pieces
  • 10×17 board
  • three-number target matching
  • target progression
  • scanner
  • combo system
  • scoring
  • game over
  • victory
  • mobile controls
  • leaderboard
  • basic audio
  • basic presentation

Additional systems are only justified when they improve the central gameplay loop.

42. Scope Management

One of the biggest lessons from the project was that the danger was not a lack of ideas.

The danger was losing the project's scope.

The central design principle became:

Good game design is not about having ideas. It is about having the ability to remove and add ideas without damaging the core experience.

During development, ideas were evaluated by asking:

  1. Does this support the core?
  2. Does this add meaningful player experience?
  3. Does it fit the project's scope?
  4. Does removing it damage the game?

This kept FiveTen focused.

43. What FiveTen Should Never Become

FiveTen should never become:

  • a conventional math worksheet disguised as a game
  • an overcomplicated falling-block system
  • a game overloaded with unrelated abilities
  • a UI-heavy educational application
  • a game where the narrative overwhelms the mechanics
  • a game where effects make numbers difficult to read

The mathematical mechanic must remain the center.

44. Design Philosophy

FiveTen's design philosophy is based on simple rules producing deeper consequences.

The game should be:

  • immediately understandable
  • difficult to fully master
  • flexible in solution
  • readable
  • rewarding
  • playful
  • compact

Depth should come from interactions between systems rather than from simply adding more systems.

45. Portfolio Value

FiveTen demonstrates more than the ability to make a prototype.

It demonstrates:

  • shipping a complete game
  • designing a core mechanic
  • iterating through playtesting
  • balancing difficulty
  • designing mobile controls
  • designing feedback systems
  • designing progression
  • managing scope
  • implementing leaderboards
  • considering monetization
  • solving technical production problems
  • observing player behavior and responding to it

The project also demonstrates a design process rather than only a final product.

46. Final Design Summary

FiveTen asks a simple question:

Can addition become a real arcade puzzle game?

Its answer is built through falling pieces, target-based decisions, scanning rhythm, combos, special abilities, and increasingly demanding board management.

The game's strongest design quality is not the number of systems it contains.

It is the way those systems reinforce the same core activity:

Think → place → anticipate → calculate → clear → improve.
